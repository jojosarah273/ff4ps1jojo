# Reading the port (a guided tour)

This is the SoH-style map: how the interpreted deck fits together, where
the names come from, and where a modder would hook.

## The five layers

```
 config/battle/shop/event menus   <- hand-written drivers (root.c, rows.c...)
   |       call the window API
   v
 window API   port/include/ff4_window.h   (0x800F primitives, semantic names)
   |       implemented by the device + db modules
   v
 db layer     port/src/db/*   (catalog base, cell register file, tickers)
   |       reads/writes the 0x800D bank
   v
 device       port/src/device/sdl_device.c   (SDL window, cells->pixels, input)
   |
   v
 SDL2 / host OS
```

## Where the names come from

- Every interpreted primitive has a semantic name in
  `tools/port_names.py` (`NM` table) and is declared in
  `port/include/ff4_window.h` (calls in the deck are renamed to these,
  ~93% of the raw ids eliminated).
- The full catalog — every Phase A function, its name, its module, and
  its byte-verified status — is `port/docs/functions.md` (generated by
  `tools/port_catalog.py`; refresh with `python3 tools/port_catalog.py`).
- Module format contract: `port/FORMAT.md`.
- Ground truth: each module names the `src/func_*.c` it mirrors.

## Typed state

- `port/include/ff4_state.h` — `menu_cell_state_t` is the typed read of
  the six cell registers; `input_state_t` is the host input latch.
  New code talks to these; `menu_cell_read/apply` move the same bytes as
  the flat D_8019EDxx globals (db/cells.c), so nothing is reinterpreted.

## Modder hooks (Phase C territory, but the seams exist now)

- **Input**: replace `device_poll_events` in sdl_device.c,
  or the `io_just/io_poll` implementations, to remap keys.
- **Menus**: the config root (`port/src/config/root.c::config_menu_run`)
  drives the option-list state; row order is in `options.c`/rows modules.
- **Data**: the catalog base/offset machines in `port/src/db/catalogs.c`
  are where "the table the menus read" gets sourced — the randomizer
  corpus feeds here.
- **Rendering**: `cell_text`/`put_text` in sdl_device.c convert the
  0x20xx catalog codes to pixels; real glyphs replace hex ids once the
  disc text atlas is decoded.

## Naming policy (why names are conservative)

Names describe what the asm demonstrably does (cells touched, bits set),
never invented intent — the decomp discipline of "no fabricated flow"
carried into naming. `cell_pos_fwd` means "the position counter advances",
not "the player walks forward".
